# Pakka · RTO shield for COD orders (startup concept + working demo)

**Live demo:** https://yashsarkar1806-creator.github.io/pakka-rto-shield/

A fictional startup I designed end to end as a marketing portfolio piece: the problem, ICP, positioning,
go-to-market, pricing and metrics, plus a landing page with a working risk-scoring demo and ROI calculator.

**The idea:** Indian D2C brands lose margin on cash-on-delivery (COD) orders that get refused or can't be delivered
and travel back to the warehouse (return-to-origin, or RTO). Pakka scores each COD order at checkout and runs the
right fix (ship, WhatsApp confirmation, prepaid nudge, or hold), so brands keep COD conversion without paying for returns.

> Pakka is not a real company. The model is trained on **synthetic** data and every price and planning number is an assumption.

## Demo model (synthetic)

Eight signals: first-time customer, tier-3/rural pincode, order value, address quality, late-night order,
past RTOs on the phone number, discount depth, and whether the phone was confirmed.

On a 25% holdout of the synthetic orders (base RTO rate 26%), the model reaches an AUC of 0.73, and its riskiest
20% of orders contain 40% of all RTOs (about 2x lift). These figures only prove the pipeline works end to end;
they say nothing about real-world performance, because the data was generated from rules I wrote.

## Run it

```bash
# landing page: open docs/index.html, or serve it
python3 -m http.server -d docs 8000

# retrain the synthetic model (regenerates data/, model/ and docs/weights.js)
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python model/train_model.py

# unit tests for scoring, explanations, ROI maths, plan picker and UTM parsing (Node 18+)
node --test tests/
```
